# Messages and remote callbacks

Admission rejects self-sent and untrusted traffic before decoding, then checks channel identity and a usable event source. Responses must also match the pending request's target window and expected origin. Request handlers receive browser-verified source metadata, not the metadata claimed in the envelope.

The request integration runs the handler, builds a response, and posts it. A request with no handler is answered with `VERSION_MISMATCH`, so a peer on another version fails fast instead of at its timeout. Every outgoing message is JSON-encoded through `stringifyForWire`, so an unencodable value such as a `BigInt` rejects as `VALIDATION` with the encoder's error as `cause`. If the result cannot be serialized, an error response is sent instead. An error response carries the `ForgeFrameError` code of an error ForgeFrame raised, and the receiver rebuilds a `ForgeFrameError` for a known code. A remote callback's own failure is sent without a code, even when it is a `ForgeFrameError`, so callers receive a plain `Error`; the exception is a relayed remote wrapper the bridge itself created (a peer's export registered by the consumer's relay), whose own failure, such as `CLOSED`, keeps its code. Timeouts and teardown reject pending requests. Remote callback calls (CALL and PEER_CALL) have no timeout, because the callback may still be running in the other window: they settle with its result, or reject on teardown or, for consumer calls, when the host reconnects with a new session. A props update still waiting when a new host session's BOOTSTRAP arrives resolves at once (`resolvePending`), because the snapshot that BOOTSTRAP reads already carries it; bootstrap therefore never waits behind it for the acknowledgement timeout. Host teardown posts a one-way TEARDOWN notice; the consumer then rejects its calls to that window, including calls the host never dispatched, and rejects later calls until the host starts a new session with BOOTSTRAP or INIT. While calls to a window are pending, the bridge checks every 10 s that the window still answers on a separate liveness channel; an unanswered check rejects them, which covers documents that go away without teardown, such as a navigated iframe or an unloaded consumer page.

Messenger requests encode the full envelope before allocating a pending request and signal the delivery attempt immediately before posting. Prop and export batches abort newly registered callbacks when encoding fails before that point, and conservatively keep them after a post was attempted. Unknown thrown values are normalized without letting diagnostic coercion throw, so callback errors always reach the response path.

The function bridge:

- **Identity.** Local functions get stable IDs while retained. Remote wrappers are cached by ID, window, and origin; the remote cache evicts beyond 500 entries. Local callable references are never evicted to admit another callback.
- **Capacity.** Each prop or export snapshot admits at most 500 distinct functions. New registrations are staged and callable during delivery. An update batch removes stale references once acknowledged; a bootstrap batch completes as soon as serialization finishes. A serialization failure before delivery rolls back only new registrations. A delivery failure conservatively keeps previous and possibly delivered references in a pool capped at 1,000 and rejects further registrations until an acknowledged retry with retained callbacks or a new session frees capacity.
- **Reconnection.** The verified new-session reset runs inside queued bootstrap serialization after earlier updates settle. It releases callable registrations but keeps weak IDs, so callbacks the new host already acknowledged keep their identity when re-registered. Teardown clears both registrations and weak IDs.
- **Peer relay.** Peer exports go through a separate `PEER_CALL` relay bridge with the same source checks. Selection is pure policy over peer facts observed from each indexed instance. Discovery takes the requester's uid and tag from the consumer instance rather than the request, and is opt-in on both sides: a requester whose component has no `peers` option is refused with a `VALIDATION` error, and only components that set `peers` are listed. It returns only peers whose verified host origin equals the requesting host's browser-reported origin, including with `allTags`; a peer's `peers` matcher may admit other requesting origins. Opaque (`"null"`) origins are distinct from one another, so an opaque requester receives no peers and a peer whose own host is opaque is never listed, even when its matcher matches; the messenger never admits an opaque sender, even under `'*'`. A peer whose host is still loading is matched by the origin the consumer opened it at and listed without exports; instances that were never opened are omitted. Discovery uses append transactions with a cumulative 500-reference bound; a failed serialization rolls back the additions without retiring held peer snapshots. Held snapshots survive prop batches and repeated discovery; replacement exports retire their original source functions. Reconnection clears old requester relay identities, and teardown clears both bridges.
- **Codec.** Props and exports share one recursive bridge codec. Codec guards require the complete own-property shape of transport wrappers. Encoding escapes ordinary records shaped like function, `Date`, or escaped-record markers, including the escaped-record marker itself, after their fields are converted, so a custom `toJSON()` that produces a marker shape still arrives as data. Marker fields written as native raw JSON count as the value their text represents. Codec-generated function and `Date` markers keep their identity, and decoding restores escaped fields as data rather than as a function or `Date`. Serialization handles `Date` framing, cycles, and unsafe-key filtering, converts objects other than arrays, dates, and native raw JSON through `toJSON(key)` and primitive unboxing once, and reads arrays entry by entry; decoding reconstructs function references and `Date` wrappers together. These encoding callbacks run inside the transport-owned serialization batch.
