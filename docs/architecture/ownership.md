# Subsystem state ownership

Paths are relative to `packages/forgeframe/src`.

| Subsystem | Entry points | Owned state and work |
| --- | --- | --- |
| Component definitions | `core/component.ts` | `create()` has one inference-only signature: props, factory input and exports come from the `props` and `exports` schemas, and the factory's props argument is required exactly when a key of the inferred input is. It validates declarations, including the `context` option through `core/render-context.ts` (the rule `render()` also applies), origin matchers (which reject strings without a scheme and any `*` other than a leading host label), the `exports` schema, and removed or renamed options (`allowedConsumerDomains`, `eligible`, `children`, `peerDomains`, `domain`, `timeout`, `defaultContext`), each with a `VALIDATION` error naming its replacement, keeps its own copy of the options and of each wrapped prop definition, constructs factories, and tracks each factory's instances. `Component.instances` returns a new frozen snapshot on each read, so callers cannot desynchronize the factory list from the instance index. `closeAll()` closes every instance in the global index concurrently and rejects with an `AggregateError` after all closes settle. Defining a component never starts or configures a host, and the module does not import the host runtime. The registry and instance index own their maps; `initHost(Component, ...)` reads a factory's tag, definitions and `exports` schema through the registry's options symbol. |
| Consumer lifecycle | `core/consumer.ts` | Options, lifecycle flags, render task, events, exports, and cleanup coordination. |
| Consumer props | `core/consumer/props-pipeline.ts` | Raw and normalized snapshots, deferred construction-time normalization failures, the serialized update queue and the render hold. `prop-update.ts` holds the pure update policy: patch merge, normalization keys, normalized overlay, revalidation keys and the update delivery origin. |
| Consumer rendering | `core/consumer/renderer.ts` | Container, owned wrapper, iframe, and prerender element. `render/` implements browser effects and templates; `popup-layout.ts` calculates geometry and polling backoff from supplied data. |
| Consumer transport | `core/consumer/transport.ts` | Host window, opened/active origins, the static URL origin trusted when no `hostOrigins` is set (kept through teardown, so it always mirrors the messenger's trust), bootstrap session, initialization deferred, messenger, prop function bridge, and a separate peer relay bridge. |
| Host lifecycle | `core/host/bootstrap.ts`, `core/host/component.ts` | The single active host, host identity, consumer window and messaging origin, readiness, deferred INIT, and destruction. Callers reach the runtime only through the frozen `Host` handle: `ready` (which resolves to the consumer's props alone), `uid`, `tag`, `consumerOrigin`, the host controls, `onProps()`, `init()`, `destroy()`, `on()` and `once()`. Controls live on the handle, not on the props, so only `then` and `children` are reserved prop names (`core/host/reserved-props.ts`). `init-host-arguments.ts` checks `initHost()` arguments and reads no browser globals. |
| Host props | `core/host/props-runtime.ts` | Consumer snapshot, stable built-in host API, pending bootstrap props, and subscribers. |
| Host security | `core/host/security.ts` | Reads browser origin evidence; a window without a parent or opener is the one `CLOSED` start-up error (marked, so no other `CLOSED` error is mistaken for it), which `initHost()` turns into `null`. `consumer-origin-policy.ts` decides trust from that evidence and reads no browser globals. `consumerOrigins` is required in every `initHost()` form and validated before use, so a missing allowlist or an empty or blank string throws instead of trusting every consumer; `'*'` is the explicit opt-in, and the host still binds the exact verified http(s) origin. |
| Host transport | `core/host/transport.ts`, `core/host/peer-instances-options.ts` | The one-time INIT send, session ID, outbound export queue, messenger, export bridge, and peer-call decoding bridge. `peer-instances-options.ts` checks `getPeerInstances()` options before a request is sent. |
| Messaging | `communication/messenger.ts` | Trusted matchers, pending correlated requests, message handlers, and listener lifetime. A messenger never trusts an opaque (`"null"`) origin, its own or a sender's, even under `'*'`, and consumer messengers listen only once host content opens. Requests go only to the origin of an absolute URL target; `"*"`, `"/"`, other strings, and opaque-origin URLs are rejected before posting. `protocol.ts` owns envelopes and encoding. |
| Function bridge | `communication/bridge.ts` | Local callable IDs, remote wrappers, capacity, and serialization batches. Recursive codecs define the wire semantics. |
| Props and schemas | `props/normalize.ts`, `props/exports.ts`, `props/prop/`, `props/definition-checks.ts` | Schema-driven normalization, output validation, the exports check (`validateExports`, the same unchanged-output rule as props), the pure delivery policy for `sendToHost` and `deliverTo`, immutable builders, schema issue paths, and the declaration checks (removed and unknown options, required `schema`, `deliverTo` matchers, a boolean `sendToHost`, parameter names and their clashes) shared by `create()` and `initHost()`. Only compiled definitions are cached. |
| React adapter | `react.ts` (`forgeframe/react`), `drivers/react.ts` | Imports React directly (an optional peer dependency). `createReactComponent` checks its arguments (one component, no reserved wrapper prop names) and names the wrapper `ForgeFrame(<tag>)` from the registry's options. Hook and ref ordering and React render state live in the wrapper. `react/lifecycle.ts` coordinates a mounted instance and its `instanceRef` handle; `react/prop-sync.ts` owns queue operations and draining. The wrapper owns the refs. |
| Supporting operations | `window/`, `utils/`, `events/` | Window adapters and bootstrap metadata, dimensions, origin matching and matcher validation (`utils/origin-pattern.ts`: `'*'`, exact origins, and `scheme://*.rest` for one or more leading labels), wire JSON encoding (`utils/json.ts`), the opaque-origin check (`utils/origin.ts`), wire values, promise and cleanup resources, IDs, and event subscriptions. |
| Errors | `errors.ts` | `ForgeFrameError` and the `ForgeFrameErrorCode` union, plus the wire helpers that send a code with an error response and rebuild a coded error from one. Every error ForgeFrame raises is a `ForgeFrameError`, except the build-time version check; errors from application code pass through, and `normalizeError()` keeps a non-`Error` thrown value as `cause`. |
