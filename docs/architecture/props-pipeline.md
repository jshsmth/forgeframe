# Props update pipeline

`updateProps()` → serialized queue → isolated patch merge → schema conversion (which applies schema defaults) → self-acceptance checks (each schema accepts its own output unchanged) → component `validate` → URL/origin checks → snapshot commitment → optional host synchronization → prop notifications.

- **Presence and defaults.** The schema is the only source of a prop's presence, default, and value, in the direct and the wrapped form and on both sides. Normalization runs each defined prop's schema on the supplied value, including `undefined` for an omitted prop, so a schema that rejects `undefined` makes the prop required and the missing value fails with the schema's "Validation failed" message. No user code receives instance controls during construction.
- **Presence in patches.** `undefined` means "not supplied" in the factory input, update patches and React props. The patch merge deletes a key whose value is `undefined` from the raw input snapshot, so the raw snapshot never holds an own `undefined`. An update normalizes only the patched keys (every key while a construction failure is pending), so a reset key takes its schema default again, an optional one has no value, a required one rejects the update, and unchanged keys keep their normalized values. The normalized snapshot keeps every declared prop as an own key. Rechecks skip the keys the update has just normalized.
- **Deferred failures.** A schema failure during construction does not throw. The instance keeps a best-effort snapshot that is never delivered and rethrows the failure at render, at each trust boundary, and for updates until one normalizes every prop successfully.
- **Own properties.** Prop keys are read from own properties. Host validation treats omitted inherited names as missing, and reconciliation removes stale custom keys by own membership in the new snapshot. Shaped object schemas also read only own fields; omitted nested fields reach presence validation as `undefined`, including names inherited from `Object.prototype`.
- **Built-in schema rules.** String URL schemas accept parseable absolute HTTP(S) URLs, return the input unchanged, and compose with patterns. Number schemas accept only finite numbers, so JSON transport cannot turn them into `null`. Refinements accumulate as ranked checks instead of overwriting each other, so `.email().pattern()` and `.min(10).positive()` enforce both rules.
- **Undefined definitions.** Prop-definition entries set to `undefined` are dropped, so the prop is neither normalized nor sent, as for any undeclared input; a host drops a delivered field whose definition entry is `undefined`, as for an undeclared one. Declaration admission applies the same rule to reserved names; real definitions of `then` and `children` are rejected. Before registering a factory or creating a host runtime, `create()` and `initHost()` reject a getter- or setter-defined entry, or a wrapped `schema`, `deliverTo`, `sendToHost`, `queryParam` or `bodyParam` field that is an accessor or inherited (they are read again at normalization and delivery), a wrapped definition without a `schema`, one that sets a removed option (`serialization`, `required`, `default`, `value`, `decorate`, `hostDecorate`, `validate`, `alias`, `sameDomain`, `trustedDomains`, `outputSchema`) with an error naming its replacement, an invalid `deliverTo`, and a `queryParam` or `bodyParam` that is not a boolean or a non-empty name.
- **Defaults and outputs.** Callback schema defaults are factories that return the callback; the factory result is checked without invoking the callback. Optional and nullable presence carries through, and non-function defaults are evaluated directly; `prop.*` copies array, plain-object and `Date` defaults on each use, copying shared and cyclic references once, so instances never share them. A default removes `undefined` from a schema's output type unless the default can be `undefined`. Each prop has one schema, and each normalized value must pass that schema unchanged (`validateUnchanged`, shared by normalization, the consumer's rechecks and host validation). Normalization reports a violation as a definition mistake; trust boundaries recheck supplied inputs and normalized outputs, so a mutated input or output is caught before it is used. `prop.object`, `prop.record`, `prop.tuple`, `prop.union` and `prop.array` reject a missing nested schema when they are built.
- **Async schemas.** Unsupported asynchronous schema results are observed without being awaited. Validation, default, output, and nested-schema probes refuse them synchronously and do not produce unhandled rejections. Promise detection works across realms, including inside composite schemas.
- **Arrays.** Deliverable normalized arrays reject `undefined` entries and sparse holes before render resources are created or an update is committed. Delivery policy runs first, so local-only and withheld values are exempt. Custom JSON encoders run at delivery, and the arrays they return are checked then. Bridge guards stop `undefined` entries in delivered props and exports, including arrays a custom `toJSON()` returns, from becoming `null`. Item defaults are applied before these checks; standalone optional schemas are not affected.
- **Delivery policy.** One pure decision over the definition and the observed host decides delivery: a prop is delivered when `sendToHost` is not `false` and `deliverTo` is absent, is `'same-origin'` and the host is verified to share the consumer's origin, or is a matcher that admits the host origin. Bootstrap and updates use the browser-verified host; the initial query and POST body use the pinned URL's origin and treat the host as not yet same-origin, so `'same-origin'` props never enter the initial request. The host evaluates the same decision with its own origin and the verified consumer origin.
- **Parameters.** `queryParam` and `bodyParam` name the parameter (`true` for the prop key). Encoding is a data operation: dates become ISO strings, other objects JSON, and functions, `undefined`, `null`, invalid dates, and JSON-undefined objects are omitted.
- **Commitment.** Candidate preparation never replaces the current snapshot, so validation or origin failures leave the previous snapshot intact. Commitment happens before host synchronization; a transport failure does not roll back the committed consumer state.
- **Queue.** Queue entries are installed before schema transforms or the component `validate` can re-enter, including before a host connects. The first update outside a render hold starts synchronously; later entries run in FIFO order, and a failure does not block later entries. Host bootstrap and updates share the queue, so bridge batches never overlap. A render attempt's hold is one more entry: updates admitted after it wait without running user code, the render's own bootstrap reads run inside it, and it releases once when the attempt settles. Teardown abandons the queue tail and releases the hold, so every held update settles.
- **Host side.** The host deserializes, validates each expected prop with the same schema the consumer used (a value the schema rejects or changes rejects the snapshot), and filters before reconciling. Stale keys are removed from the live props object, and `then` and `children` are dropped from every snapshot, so an unchecked consumer cannot make it a thenable. `host.onProps` is the only way to observe updates, and it returns an unsubscribe function. Subscriber registrations are snapshotted after commitment: new or re-registered observers wait for the next update, and cancelled registrations are skipped. Unsubscribe functions capture their registration token, so a stale handle cannot remove a later registration of the same callback. Async subscriber failures are caught without awaiting subscriber work or delaying acknowledgement. A newer acknowledged update that arrives during bootstrap wins over the older bootstrap snapshot. Updates acknowledged before bootstrap completes are committed without notifications; bootstrap then publishes the final snapshot once. The props object `ready` resolves to keeps its identity; each `onProps` notification receives the new snapshot.

## Consumer-only and withheld props

The host expects only the props delivered to it: it drops definitions that set `sendToHost: false` and those whose `deliverTo` excludes its origin, using its own origin (read when the host starts) and the verified consumer origin. Fields for the other definitions are discarded before decoding bootstrap or update snapshots, including values sent by stale or misconfigured consumers, so they never enter host state or notifications. Every expected prop is validated with its output schema, or its schema, present or not; withheld props are neither required nor accepted. Consumer validation still applies every definition. Undeclared fields, including those of `undefined` definition entries, are discarded the same way. Only a tag-agnostic host started without `props` keeps every field, unvalidated; the component form always has definitions, empty for a component without `props`.

Host definitions are fixed when `initHost()` starts the runtime. A pending bootstrap selects the latest acknowledged wire snapshot and filters it with those definitions before commitment, so consumer-only and withheld fields cannot return.
