# ForgeFrame Test Index

What each test file covers, how to run it, and how to choose new tests. Paths are relative to `packages/forgeframe/tests`.

## Commands

| Task | Command |
|------|---------|
| Run unit and integration tests | `npm run test:run -w forgeframe` |
| Run them with coverage thresholds (no separate test run needed) | `npm run test:coverage -w forgeframe` |
| Run one file | `npm run test:run -w forgeframe -- tests/unit/<file>.test.ts` |
| Typecheck type assertions and all unit, integration, and browser fixtures | `npm run typecheck:tests -w forgeframe` |
| Typecheck integration fixtures only | `npx tsc -p packages/forgeframe/tests/integration/tsconfig.json --noEmit` |
| Run browser tests (repository root) | `npm run test:browser` |

## Unit tests (`unit/`)

- `bridge.test.ts`: Function bridge serialization and deserialization, remote call dispatch, 500-callback admission, remote wrapper cache eviction, full snapshot replacement, duplicate identity reuse, staged calls, rollback, bounded delivery recovery, append capacity, a timed-out liveness check that ignores calls a newer watch tracks, and reset/teardown. Retention is checked by whether a released callback's call rejects and a retained one still answers.
- `company-demo-payment-policy.test.ts`: Browser-independent playground payment rules: merchant session and result admission, receipt commitment and isolation, unpaid decline and retry, mismatch and duplicate rejection, malformed callback and receipt fields, ISO calendar/time validity, snapshot ownership, retry after rejection, payment availability, provider simulation, demo-card normalization, and acknowledgement admission with invoice correlation.
- `component-clone.test.ts`: Clone snapshots, lifecycle tracking, peer visibility, global and tag cleanup. Repeated and reentrant `close()` calls resolve only after deregistration and destruction notifications, including while failed-render teardown is in progress. A rearmed `once` observer waits for the next public resize.
- `component-instance-index.test.ts`: Internal active-instance indexing, reindexing, tag clearing, and peer lookup snapshots.
- `component-node-runtime-transition.test.ts`: Component registration across a Node-to-browser runtime transition: relative URLs defer domain validation until a browser can resolve them.
- `component.test.ts`: Component creation, registration, instance lifecycle, and host-context detection. The removed `allowedConsumerDomains` option throws a migration error before registration. Undefined reserved definition entries are treated as omitted; real host-control definitions are rejected. The removed `serialization` option is rejected for any defined value before registration, and accepted when set to `undefined`. Peer discovery is limited to the requester's verified host origin unless a peer's `peerDomains` admit the requester, peers still loading are listed without exports, and peers whose own host is opaque are never listed. Empty or blank `domain` and `peerDomains` values are rejected, and a consumer adds a `message` listener only when it opens host content.
- `consumer-branch-coverage.test.ts`: Consumer edge paths for domain trust, rendering, prop sync (callback release checked through bridge calls), and resizing a popup that is not open.
- `consumer-lifecycle.test.ts`: Consumer handshake, lifecycle messaging, open/close guards, update validation, and `GET_SIBLINGS` scoping to the requester's own uid, tag, and verified host origin regardless of claimed or malformed request fields, with no peers for opaque (`"null"`) origins.
- `consumer-navigation.test.ts`: Relative URL origin admission, declaration and render base changes, pinned destinations, and fragment-bearing navigation.
- `consumer-origin-policy.test.ts`: Messaging-origin validation of supplied origins: only an exact HTTP(S) origin is accepted.
- `consumer-props-queue.test.ts`: Disconnected reentrant updates, FIFO failure recovery, render admission draining, matching initial request and bootstrap snapshots, and cancellation.
- `consumer-renderer.test.ts`: Renderer ownership of iframe and popup resources, loading completion, configured CSS preserved through the loading transition, eager/lazy loading concealment, show requests made before frame creation, latest show/hide precedence, custom shell and control preservation, templates, form cleanup after submission failure, mount-document prototypes, and teardown.
- `consumer-transport.test.ts`: Trust rotation, failed prop sync cleanup, handshake waiting, INIT admitted only for the latest verified bootstrap session, a host-reported init failure that only its own handshake reports, a timeout that otherwise hints that consumer and host must run the same ForgeFrame major version, and release of a full recovery pool only by a verified new bootstrap session.
- `dimension.test.ts`: Popup pixel conversion and fallbacks for nonpixel and nonfinite input; iframe CSS units pass through.
- `domain-pattern.test.ts`: Wildcard domain compilation cache and stateless `RegExp` trust checks.
- `emitter.test.ts`: Subscription order, `once`/`off` (including `off()` cancelling a pending `once` and stale unsubscribe handles keeping newer registrations), async error isolation, removal of a specific listener or all listeners, during dispatch or between emissions, and deferral of listeners added during dispatch.
- `error.test.ts`: Unknown-error normalization keeps `Error` identity and ordinary coercion, with a stable fallback when coercion throws.
- `host-branch-coverage.test.ts`: Host edge paths for INIT timing, INIT delivery failures reported on `host.on('error')`, and guards, with INIT carrying only the bootstrap session ID and GET_SIBLINGS only the caller's options.
- `host-lifecycle.test.ts`: Host lifecycle messages with a stubbed bootstrap response, `hostProps` synchronization, consumer window resolution, channel metadata left in `window.name` after `initHost()`, host-side output-schema and `sameDomain` rejection of a bootstrap snapshot (including for a verified same-origin host), built-in and snapshot identity, consumer-only fields kept out of an update acknowledged during a pending bootstrap, and one notification with children attached when bootstrap completes after an earlier update.
- `host-security.test.ts`: Host allowlist enforcement through `consumerOrigins`, rejection of empty, blank, `null`, and malformed allowlists, an empty array that admits no consumer, and a wildcard pattern that binds the verified origin. The messaging target prefers a directly readable consumer origin; an unreadable consumer receives the bootstrap request only at an exact, allowlisted claimed origin. A failed allowlist check keeps the channel metadata for a same-page retry.
- `host-transport.test.ts`: A one-time INIT send that waits for bootstrap and never follows teardown, INIT and GET_SIBLINGS data without host-claimed identity, props routing, a `focus()` that waits for window focus with a bounded wait or skips it when the consumer page reports no focus, and teardown, which is not reported as an INIT failure.
- `iframe-configuration.test.ts`: CSS and boolean/string attribute encoding.
- `iframe.test.ts`: Iframe element creation (attributes, styles, CSS variables and dimensions), reserved-attribute guards, a sandbox attribute in any letter case, the default sandbox for `false` values, destruction, visibility, and sizing. `consumer-branch-coverage.test.ts` covers the default, explicit and empty sandbox through the consumer.
- `index-node-smoke.test.ts`: Public entrypoint imports and component definitions without browser globals. The entrypoint has no `default`, `ForgeFrame`, `getHostProps`, `isEmbedded`, or `PROP_SERIALIZATION` export; `initHost(Component, { consumerOrigins })` returns `null`, while a bare `initHost()` still throws.
- `index-side-effect-free.test.ts`: Importing the public entrypoint has no side effects until `initHost()` is called in a ForgeFrame host window, and no `hostProps` window global is ever defined.
- `messenger-routing.test.ts`: Multi-instance channel routing and function bridge response isolation.
- `messenger.test.ts`: Request/response flow, filtering, trust checks (no self-trust for an opaque origin), targets normalized to an absolute URL's origin with `"*"`, `"/"`, other strings, and opaque-origin URLs rejected before posting, deferred listening, `rejectPending` filtering by message type and window, and teardown (no further requests handled, sends and posts refused).
- `package-contract.test.ts`: ESM package exports, README package claims, release scripts, release tag validation, and the bundle size budget check.
- `playground-code-generator.test.ts`: Executes generated iframe, popup, and modal examples, which use the named `create` and `prop` imports, with empty props, composite values, callbacks, quoted names, and styles. Copied popup dimensions match live rendering; playground-owned callbacks replace editor-added definitions of the same name without duplicate object keys.
- `playground-props-bar.test.ts`: Quoted prop names and values, typed JSON edits, preservation at render time, invalid input recovery, rejection of every reserved host-control name before mutation, and modal schema cache invalidation.
- `playground-test-lab.test.ts`: The test lab keeps running after a failure, links the affected route, and renders failure text as text.
- `playground-text-rendering.test.ts`: Literal prop keys, values, and identity text, logger text, update IDs, and preserved host controls.
- `popup-layout.test.ts`: Popup geometry and polling backoff from supplied screen dimensions.
- `popup.test.ts`: Popup open, close, focus, and resize helpers, nonpixel resize fallbacks, reported resize denial for cross-origin windows, close detection, and popup-blocker detection through `openPopup` (null, closed, zero-size, and inaccessible windows).
- `prop-schema.test.ts`: `prop` builders and Standard Schema compliance: accumulated string, number, date, and array refinements and their check order, rule-specific messages for `NaN` and sign constraints, nonfinite-number rejection, own-field omission and defaults for inherited names in shaped objects, HTTP(S) URL validation with composable constraints, trimming before length checks, literal optional/default clones, and union continuation after literal/enum rejection of BigInt, cyclic, or custom-encoder input without JSON diagnostics. Enum values, object shapes, and tuple/union definitions are copied at construction, including null-prototype arrays and shadowed iterators, so later caller mutation has no effect.
- `prop-update.test.ts`: Isolated patch/reset merging and validation-key bookkeeping.
- `props-alias-materialization.test.ts`: Alias-chain resolution, precedence, reset propagation, explicit clearing, and cycle safety.
- `props-alias-updates.test.ts`: Alias precedence in the consumer update pipeline, validation rollback, and preservation of materialized values.
- `props-removed-options.test.ts`: The removed-option policy shared by `create()` and `initHost()`, beyond the public `component.test.ts` cases: non-string `serialization` values are rejected, accessor-defined entries are not invoked, and direct schemas, `undefined` entries, and inherited fields are ignored.
- `props-serialize.test.ts`: The props codec's own root rules: undefined key omission and the `__proto__` filter on decode, which only a crafted message reaches.
- `props.test.ts`: Prop normalization, own canonical/alias selection for inherited names, schema validation, host/query/body filtering and conversion, and default normalization and delivery for omitted built-in definitions.
- `protocol.test.ts`: Message factories, serialization, and prefix validation.
- `react-driver-lifecycle.test.ts`: Lifecycle fault injection: stale completion and rejection isolation, cleanup order, unavailable mounts, and context changes. Public refs and observers are covered by `integration/react-host-sync.test.ts`.
- `react-driver-prop-sync.test.ts`: Queue fault injection: failed acknowledgement recovery, retries of equivalent in-flight or queued commits, and throwing observers. Public FIFO, omission, and validation behavior is covered by `integration/react-host-sync.test.ts`.
- `react-prop-queue.test.ts`: Queue acknowledgement, requested retries, and reset payloads without mounting React.
- `realm-values.test.ts`: Cross-window `Date` and ordinary-record recognition, class and array rejection, and codec array values.
- `render-templates.test.ts`: Template DOM creation, styles, and the prerender swap, including its fade timing and a visibility request that keeps content hidden.
- `schema-contract.test.ts`: Contract coverage against Zod and Valibot.
- `schema-interoperability.test.ts`: Minimal Standard Schema shapes, callable (ArkType-style) schemas through validation and render admission, and optional metadata.
- `schema-path-format.test.ts`: Error paths that mix key and index segments.
- `schema.test.ts`: Standard Schema detection, schema-aware prop validation, and handling of unsupported rejected native and foreign promises in direct and nested schemas.
- `url.test.ts`: Relative URL resolution and query appending that keeps fragments, existing encoding, and duplicate parameters.
- `utils.test.ts`: UID, cleanup manager, and promise utilities.
- `version.test.ts`: `VERSION` matches package metadata.
- `window-helpers.test.ts`: Domain checks, opener and consumer lookup, and iframe/popup detection.
- `window-name-payload.test.ts`: Window-name envelope encoding and its size limit, protocol classification of decoded payloads (current, an older protocol with its channel fields and package version, a newer protocol by its tag alone, or invalid edge shapes), reads that never write `window.name`, and ForgeFrame-window detection, including windows whose name cannot be read.

`react-driver-test-harness.ts` provides deterministic hook and component mocks for the React driver tests.

## Browser tests (`browser/`)

Each suite runs in Chromium, Firefox, and WebKit against separate local origins. Install the engines with `npx playwright install chromium firefox webkit`, then run `npm run test:browser` from the repository root. CI installs browser system dependencies and runs on Node 24. WebKit covers the Safari engine; it does not replace testing on physical Safari or devices.

  - Host teardown: a call posted behind an export that destroys the host, and a later call, both reject instead of waiting forever.
  - Recovery: failed-schema retry, a component-form retry whose second host gets fresh props and working controls, updates pending at bootstrap, and callback updates queued during reconnection.
  - Initial navigation: real iframe/popup GET and POST requests, relative URL policies with cross-origin `<base>` tags and callback or converter mutations, fragment preservation, queued prop snapshots, popup loading cleanup, async subscriber rejection isolation, POST field names that shadow form methods, and nested callbacks and dates at initialization and through updates.
  - Marker-shaped records as props and exports in each context, including raw JSON marker fields and records that become marker-shaped after custom JSON conversion with one encoder call per delivery.

- `playground-text.spec.ts`: Reserves both origins, then builds both playground pages, with the host allowlisting the consumer origin, and the consumer logger.

  - Two same-tag widgets on one host origin keep independent prop snapshots and callbacks, and the remaining widget keeps working after the other closes.

## Package check

`npm run test:package` packs and installs the built library in an isolated project. It compiles the README **Define a Component** and React **Basic Usage** examples under strict NodeNext resolution, checks that the removed default and host-read exports are absent, smoke-tests callback defaults and `initHost()` without browser globals, and types `initHost(Component, ...)` against the built package. React comes from the repository's pinned optional fixture dependency. Callback type fixtures require factory syntax for defaults after fluent chaining.

## Naming

- Name files `<module-or-scope>.test.ts` after the module or concern under test.
- Name top-level `describe` blocks after the primary module or behavior area.
- Write `it(...)` titles as expected behavior with explicit context, such as the function name for guard and error branches.

## Choosing new tests

Start from a supported public behavior or a reproduced failure, and an agreed public seam. Assert literal expected outcomes that do not depend on the implementation. Prefer a real consumer/host or React DOM integration when the behavior crosses layers, and adapt browser APIs at the environment boundary. Keep focused policy and resource fault-injection cases when they add distinct evidence; remove wiring assertions that public tests supersede.

Check acceptance and, where meaningful, rejection and recovery. Keep schema inputs and normalized outputs explicit in fixtures, and run `typecheck:tests` as well as Vitest. Confirm a new test fails when the behavior is removed, then restore the source before final validation. Coverage points to candidates; supported behavior and failure impact decide whether a test is worth adding. Do not add casts, mocks, exclusions, or threshold changes only to reach 100%.
