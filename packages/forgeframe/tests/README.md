# ForgeFrame Test Index

What each test file covers, how to run it, and how to choose new tests. Paths are relative to `packages/forgeframe/tests`.

## Commands

| Task | Command |
|------|---------|
| Run unit and integration tests | `npm run test:run -w forgeframe` |
| Run them with coverage thresholds (no separate test run needed) | `npm run test:coverage -w forgeframe` |
| Run one file | `npm run test:run -w forgeframe -- tests/unit/<file>.test.ts` |
| Typecheck type assertions and all unit, integration, and browser fixtures | `npm run typecheck:tests -w forgeframe` |
| Typecheck integration fixtures only | `npx tsc -p packages/forgeframe/tests/integration/tsconfig.json --noEmit` |
| Run browser tests (repository root) | `npm run test:browser` |

## Unit tests (`unit/`)

- `bridge.test.ts`: Function bridge serialization and deserialization, remote call dispatch, 500-callback admission, remote wrapper cache eviction, full snapshot replacement, duplicate identity reuse, staged calls, rollback, bounded delivery recovery, append capacity, a timed-out liveness check that ignores calls a newer watch tracks, and reset/teardown. Retention is checked by whether a released callback's call rejects and a retained one still answers.
- `company-demo-payment-policy.test.ts`: Browser-independent playground payment rules: merchant session and result admission, receipt commitment and isolation, unpaid decline and retry, mismatch and duplicate rejection, malformed callback and receipt fields, ISO calendar/time validity, snapshot ownership, retry after rejection, payment availability, provider simulation, demo-card normalization, and acknowledgement admission with invoice correlation.
- `component-instance-index.test.ts`: Internal active-instance indexing, reindexing, tag clearing, and peer lookup snapshots.
- `component-node-runtime-transition.test.ts`: Component registration across a Node-to-browser runtime transition: relative URLs defer domain validation until a browser can resolve them.
- `component.test.ts`: Component creation, registration, instance lifecycle, and host-context detection. Each removed prop option (see [architecture](../../../docs/architecture.md)) and each malformed wrapped definition (no `schema`, a blank `deliverTo`, an encoder `queryParam`) is rejected with its replacement before registration. Construction-time schema failures, including invalid coerced inputs, surface at render and are cleared by a valid update, and mutated inputs and normalized outputs are rechecked at trust boundaries. Only declared props are normalized: undeclared inputs named like removed lifecycle callbacks, `cspNonce`, or `timeout` are dropped and never called. The removed `allowedConsumerDomains` and `peerDomains` options throw a migration error before registration; `integration/instance-tracking.test.ts` covers the removed `eligible` and `children` options. Schema and component `validate` probes run the same checks render admission does (`render-validation.ts`). Undefined reserved definition entries are treated as omitted; real host-control definitions are rejected. The removed `serialization` option is rejected for any defined value before registration, and accepted when set to `undefined`. Peer discovery (with `peers` set on every participant) covers `allTags`, is limited to the requester's verified host origin unless a peer's `peers` matcher admits the requester, lists peers still loading without exports, and never lists peers whose own host is opaque. Empty, blank and empty-array `domain` and `peers` values, `peers: false`, a function `url` without `domain`, invalid `sandbox` values (non-strings, missing `allow-scripts` or `allow-same-origin`) a static `attributes.sandbox` in any letter case, and an `exports` option that is not a Standard Schema are rejected before registration; sandbox tokens are matched case-insensitively across ASCII whitespace. A consumer adds a `message` listener only when it opens host content.
- `component-events.test.ts`: The public `instance.event` subscriber, driven by public `resize()`, `focus()` and `close()` calls: registration order and typed payloads, one registration per handler, unsubscribe functions (including a pending `once` and stale handles that leave newer registrations alone), a `once` handler that rearms itself, removal and additions during dispatch, logged sync and async handler failures, a frozen object with only `on` and `once`, errors for removed event names that name the replacement and for unknown names or non-function handlers, `focus` skipped when nothing is mounted, and subscriptions after `closed` that are never called.
- `consumer-branch-coverage.test.ts`: Consumer edge paths for domain trust, rendering, prop sync (callback release checked through bridge calls), and resizing a popup that is not open.
- `consumer-lifecycle.test.ts`: Consumer handshake, lifecycle messaging, open/close guards, update validation, and `GET_SIBLINGS` scoping to the requester's own uid, tag, and verified host origin regardless of claimed or malformed request fields, with opaque (`"null"`) requests dropped even when `domain` is `'*'`, and a requester whose component has not set `peers` refused with an error naming the option. Lifecycle events: the handshake timeout and host-reported errors on `error`, `close` before `closed` once each, `render` before any frame (a `render` listener's `close()` stops the render), and a single `render` without `rendered` when close cancels a delayed render. Factory instances: repeated and reentrant `close()` calls resolve only after deregistration and `closed`, including while failed-render teardown is in progress, which emits `closed` without `close`; deregistration happens before `closed` without any public listener; and a rearmed `once` observer waits for the next public resize.
- `consumer-navigation.test.ts`: Relative URL origin admission, declaration and render base changes, pinned destinations, and fragment-bearing navigation.
- `consumer-origin-policy.test.ts`: Messaging-origin validation of supplied origins: only an exact HTTP(S) origin is accepted.
- `consumer-props-queue.test.ts`: Disconnected reentrant updates from a schema transform or the component `validate`, FIFO failure recovery, and cancellation. Render admission of earlier updates is covered by `integration/body-param-bootstrap.test.ts`.
- `consumer-renderer.test.ts`: Renderer ownership of iframe and popup resources, loading completion, configured CSS preserved through the loading transition, eager/lazy loading concealment, show requests made before frame creation, latest show/hide precedence, custom shell and control preservation, templates, form cleanup after submission failure, mount-document prototypes, and teardown.
- `consumer-transport.test.ts`: Trust rotation for static URLs only (a configured `domain` is never rotated), failed prop sync cleanup, handshake waiting, INIT admitted only for the latest verified bootstrap session, a host-reported init failure that only its own handshake reports, a timeout that otherwise hints that consumer and host must run the same ForgeFrame major version, and release of a full recovery pool only by a verified new bootstrap session.

- `consumer-peers.test.ts`: The pure peer policy: a requester without `peers` is refused; candidates without `peers` and the requester are skipped; `true` admits only the same origin while a matcher admits named origins one way; opaque origins never take part; loading peers are listed without exports and unopened ones are skipped.
- `domain-pattern.test.ts`: Wildcard domain compilation cache and stateless `RegExp` trust checks.
- `error.test.ts`: Unknown-error normalization keeps `Error` identity and ordinary coercion, with a stable fallback when coercion throws.
- `host-branch-coverage.test.ts`: Host edge paths for INIT timing, failed BOOTSTRAP requests and invalid bootstrap responses reported once on `host.on('error')` as an `Error` with the failure as its `cause`, with either `autoInit` setting, INIT delivery failures reported there, `onProps` unsubscribe functions, and guards, with INIT carrying only the bootstrap session ID and GET_SIBLINGS only the caller's options.

The messaging target prefers a directly readable consumer origin; an unreadable consumer receives the bootstrap request only at an exact, allowlisted claimed origin. A failed allowlist check keeps the channel metadata for a same-page retry.
- `host-transport.test.ts`: A one-time INIT send that waits for bootstrap and never follows teardown, INIT and GET_SIBLINGS data without host-claimed identity, props routing, a `focus()` that waits for window focus with a bounded wait or skips it when the consumer page reports no focus, and teardown, which is not reported as an INIT failure. `npm run typecheck` compiles all unit tests and fixtures through `unit/tsconfig.json` with the library's strict settings. Intentionally invalid public inputs use a documented `@ts-expect-error` at the negative fixture only.

`npm run typecheck` checks all integration files and the harness. Their TypeScript configuration keeps strict checks, and fixtures type definitions by the props they produce; Vitest runs the runtime assertions.

## Browser tests (`browser/`)

Each suite runs in Chromium, Firefox, and WebKit against separate local origins. Install the engines with `npx playwright install chromium firefox webkit`, then run `npm run test:browser` from the repository root. CI installs browser system dependencies and runs on Node 24. WebKit covers the Safari engine; it does not replace testing on physical Safari or devices.

- `navigation.spec.ts`: Builds the production library and covers:
  - Redirect isolation (the redirected page sees only channel metadata), rejection of hosts that skip the verified bootstrap, a v2 host that refuses a hand-built 1.x payload with an upgrade error and sends that consumer nothing, a component-form host opened for another tag that throws and leaves the consumer to time out, default-wrapper resizing, cross-origin popup resizing from the host with consumer-side rejection, and iframe/popup reconnection after reload and full-page navigation with current props and callable callbacks from the retained channel metadata.
  - Host teardown: a call posted behind an export that destroys the host, and a later call, both reject instead of waiting forever.
  - Recovery: failed-schema retry, a component-form retry whose second host gets fresh props and working controls, updates pending at bootstrap, and callback updates queued during reconnection.
  - Initial navigation: real iframe/popup GET and POST requests, relative URL policies with cross-origin `<base>` tags and `render`-listener mutations, fragment preservation, queued prop snapshots, popup loading cleanup, async subscriber rejection isolation, POST field names that shadow form methods, and nested callbacks and dates at initialization and through updates.
  - Marker-shaped records as props and exports in each context, including raw JSON marker fields and records that become marker-shaped after custom JSON conversion with one encoder call per delivery.
  - Arrays with null prototypes or shadowed `map` in props, updates, and exports, and repeated `close()` on rendered iframes and popups that wait for `closed`.

## Package check

`npm run test:package` packs and installs the built library in an isolated project. It compiles the README **Define a Component** and React **Basic Usage** examples under strict NodeNext resolution, checks that the removed default and host-read exports are absent, smoke-tests callback defaults and `initHost()` without browser globals, and types `initHost(Component, ...)` against the built package. React comes from the repository's pinned optional fixture dependency. Callback type fixtures require factory syntax for defaults after fluent chaining.

## Naming

- Name files `<module-or-scope>.test.ts` after the module or concern under test.
- Name top-level `describe` blocks after the primary module or behavior area.
- Write `it(...)` titles as expected behavior with explicit context, such as the function name for guard and error branches.

## Choosing new tests

Start from a supported public behavior or a reproduced failure, and an agreed public seam. Assert literal expected outcomes that do not depend on the implementation. Prefer a real consumer/host or React DOM integration when the behavior crosses layers, and adapt browser APIs at the environment boundary. Keep focused policy and resource fault-injection cases when they add distinct evidence; remove wiring assertions that public tests supersede.

Check acceptance and, where meaningful, rejection and recovery. Keep schema inputs and normalized outputs explicit in fixtures, and run `typecheck:tests` as well as Vitest. Confirm a new test fails when the behavior is removed, then restore the source before final validation. Coverage points to candidates; supported behavior and failure impact decide whether a test is worth adding. Do not add casts, mocks, exclusions, or threshold changes only to reach 100%.
