# ForgeFrame Test Index

What each test file covers, how to run it, and how to choose new tests. Paths are relative to `packages/forgeframe/tests`.

## Commands

| Task | Command |
|------|---------|
| Run unit and integration tests | `npm run test:run -w forgeframe` |
| Run them with coverage thresholds (no separate test run needed) | `npm run test:coverage -w forgeframe` |
| Run one file | `npm run test:run -w forgeframe -- tests/unit/<file>.test.ts` |
| Typecheck type assertions and all unit, integration, and browser fixtures | `npm run typecheck:tests -w forgeframe` |
| Typecheck integration fixtures only | `npx tsc -p packages/forgeframe/tests/integration/tsconfig.json --noEmit` |
| Run browser tests (repository root) | `npm run test:browser` |

## Unit tests (`unit/`)

- `bridge.test.ts`: Function bridge serialization and deserialization, remote call dispatch, 500-callback admission, remote wrapper cache eviction, full snapshot replacement, duplicate identity reuse, staged calls, rollback, bounded delivery recovery, append capacity, a timed-out liveness check that ignores calls a newer watch tracks, and reset/teardown. Retention is checked by whether a released callback's call rejects and a retained one still answers. An application callback's `ForgeFrameError` loses its code across the call, while a relayed remote wrapper's own `CLOSED` keeps it. Liveness checks are answered only for the expected peer window and rejected with `ORIGIN_REJECTED` otherwise.
- `company-demo-landing-focus.test.ts`: The playground payment host's landing focus: focus at once when accepted, a retry each animation frame while focus is refused (as WebKit refuses it in a cross-origin frame before user activation), no retry once the visitor moves focus, retries while focus stays where it was before the first attempt, and giving up after 3 seconds. The WebKit run of `browser/company-demo.spec.ts` is the regression check against the real engine.
- `company-demo-payment-policy.test.ts`: Browser-independent playground payment rules: merchant session and result admission, receipt commitment and isolation, unpaid decline and retry, mismatch and duplicate rejection, malformed callback and receipt fields, ISO calendar/time validity, snapshot ownership, retry after rejection, payment availability, provider simulation, demo-card normalization, and acknowledgement admission with invoice correlation.
- `component-instance-index.test.ts`: Internal active-instance indexing, reindexing, tag clearing, and peer lookup snapshots.
- `component-node-runtime-transition.test.ts`: Component registration across a Node-to-browser runtime transition: relative URLs defer origin validation until a browser can resolve them.
- `component.test.ts`: Component creation, registration, instance lifecycle, and host-context detection. Each removed prop option (see [architecture](../../../docs/architecture.md)) and each malformed wrapped definition (no `schema`, a blank `deliverTo`, an encoder `queryParam`) is rejected with its replacement before registration. Construction-time schema failures, including invalid coerced inputs, surface at render and are cleared by a valid update, and mutated inputs and normalized outputs are rechecked at trust boundaries. Only declared props are normalized: undeclared inputs named like removed lifecycle callbacks, `cspNonce`, or `timeout` are dropped and never called. The removed `allowedConsumerDomains` and `peerDomains` options throw a migration error before registration; `integration/instance-tracking.test.ts` covers the removed `eligible` and `children` options. Schema and component `validate` probes run the same checks render admission does (`render-validation.ts`). Undefined reserved definition entries are treated as omitted; `then` and `children` definitions are rejected, while props named like host controls (`close`, `resize`, `consumerOrigin`) are accepted. `create()` keeps its own copy of the options, so later changes to the caller's options or wrapped definitions are ignored. The removed `serialization` option is rejected for any defined value before registration, and accepted when set to `undefined`. Peer discovery (with `peers` set on every participant) covers `allTags`, is limited to the requester's verified host origin unless a peer's `peers` matcher admits the requester, lists peers still loading without exports, and never lists peers whose own host is opaque. Empty, blank and empty-array `hostOrigins` and `peers` values, `peers: false`, `peers: true` (renamed `"same-origin"`), a function `url` without `hostOrigins`, invalid `sandbox` values (non-strings, missing `allow-scripts` or `allow-same-origin`) a static `attributes.sandbox` in any letter case, and an `exports` option that is not a Standard Schema are rejected before registration; sandbox tokens are matched case-insensitively across ASCII whitespace. A consumer adds a `message` listener only when it opens host content.
- `component-events.test.ts`: The public `instance.event` subscriber, driven by public `resize()`, `focus()` and `close()` calls: registration order and typed payloads, one registration per handler, unsubscribe functions (including a pending `once` and stale handles that leave newer registrations alone), a `once` handler that rearms itself, removal and additions during dispatch, logged sync and async handler failures, a frozen object with only `on` and `once`, errors for removed event names that name the replacement and for unknown names or non-function handlers, `focus` skipped when nothing is mounted, and subscriptions after `closed` that are never called.
- `consumer-branch-coverage.test.ts`: Consumer edge paths for origin trust, rendering, prop sync (callback release checked through bridge calls), resizing a popup that is not open, and a host resize request that emits `resize` only when an iframe was resized or the host is an open popup.
- `consumer-lifecycle.test.ts`: Consumer handshake, lifecycle messaging, open/close guards, update validation, and `GET_PEERS` scoping to the requester's own uid, tag, and verified host origin regardless of claimed or malformed request fields, with opaque (`"null"`) requests dropped even when `hostOrigins` is `'*'`, and a requester whose component has not set `peers` refused with an error naming the option. Lifecycle events: the handshake timeout and host-reported errors on `error`, `close` before `closed` once each, `render` before any frame (a `render` listener's `close()` stops the render), and a single `render` without `rendered` when close cancels a delayed render. Factory instances: repeated and reentrant `close()` calls resolve only after deregistration and `closed`, including while failed-render teardown is in progress, which emits `closed` without `close`; deregistration happens before `closed` without any public listener; and a rearmed `once` observer waits for the next public resize of a mounted frame.
- `consumer-navigation.test.ts`: Relative URL origin admission, declaration and render base changes, pinned destinations, and fragment-bearing navigation.
- `consumer-origin-policy.test.ts`: Messaging-origin validation of supplied origins: only an exact HTTP(S) origin is accepted. An empty supplied origin is rejected before matching, even against `'*'`, and the allowlist check rejects a suffix-confusion origin while admitting a matching one.
- `consumer-props-queue.test.ts`: Disconnected reentrant updates from a schema transform or the component `validate`, FIFO failure recovery, and cancellation. Render admission of earlier updates is covered by `integration/body-param-bootstrap.test.ts`.
- `consumer-renderer.test.ts`: Renderer ownership of iframe and popup resources, loading completion, configured CSS preserved through the loading transition, eager/lazy loading concealment, show requests made before frame creation, latest show/hide precedence, custom shell and control preservation, templates, form cleanup after submission failure, mount-document prototypes, and teardown.
- `consumer-transport.test.ts`: Trust rotation for static URLs only (a configured `hostOrigins` is never rotated, and the trusted static origin survives teardown so a retried render on a moved base untrusts it), failed prop sync cleanup, handshake waiting, INIT admitted only for the latest verified bootstrap session, a host-reported init failure that only its own handshake reports, a timeout that otherwise hints that consumer and host must run the same ForgeFrame major version, and release of a full recovery pool only by a verified new bootstrap session. A malformed BOOTSTRAP request from the verified host (no data, no or empty session ID, a non-string ID) is rejected with `VALIDATION` before the consumer reads its props. A props send that fails before delivery releases only the new callback snapshot, and an update to a closed host window sends nothing.
- `dimension.test.ts`: Popup pixel conversion and fallbacks for nonpixel and nonfinite input; iframe CSS units pass through.
- `consumer-peers.test.ts`: The pure peer policy: a requester without `peers` is refused; candidates without `peers` and the requester are skipped; `"same-origin"` admits only the same origin while a matcher admits named origins one way; opaque origins never take part; loading peers are listed without exports and unopened ones are skipped.
- `origin-pattern.test.ts`: The leading-label wildcard (`https://*.example.com` matches one or more labels with the scheme and port fixed, not `https://evilexample.com`, a suffix host or `http://`), `'*'` compiling to any origin and misplaced wildcards to none, matcher validation rejecting `https://*example.com`, trailing and inner wildcards, scheme-less patterns and exact origins browsers never report (`https://Shop.example.com`, a default port, userinfo) while keeping custom schemes such as `capacitor://localhost`, the compilation cache, and stateless `RegExp` trust checks.
- `error.test.ts`: Unknown-error normalization keeps `Error` identity and ordinary coercion, with a stable fallback when coercion throws.
- `host-branch-coverage.test.ts`: Host edge paths for INIT timing, failed BOOTSTRAP requests and invalid bootstrap responses reported once on `host.on('error')` as an `Error` with the failure as its `cause`, with either `autoInit` setting, INIT delivery failures reported there, `onProps` unsubscribe functions, and guards, with INIT carrying only the bootstrap session ID and GET_PEERS only the caller's options. A `CLOSED` error other than the missing-consumer-window failure is rethrown by `initHost()`. A host destroyed before its BOOTSTRAP response settles rejects `ready` with `CLOSED`, reports nothing on `error` and sends no INIT.
- `host-lifecycle.test.ts`: Host lifecycle messages with a stubbed bootstrap response, live props synchronization, `then` and `children` dropped from an unchecked consumer's props so `ready` still resolves, consumer window resolution, channel metadata left in `window.name` after `initHost()`, a required `deliverTo: 'same-origin'` prop rejected for a verified same-origin host, withheld `deliverTo` props neither required nor accepted by a cross-origin host, props object and snapshot identity, consumer-only fields kept out of an update acknowledged during a pending bootstrap, and one notification, with no `children` key, when bootstrap completes after an earlier update.
- `host-security.test.ts`: Host allowlist enforcement through `consumerOrigins`, rejection of empty, blank, `null`, malformed and non-canonical (`https://Shop.example.com`) allowlists, an empty array that admits no consumer, and a wildcard pattern that binds the verified origin. The messaging target prefers a directly readable consumer origin; an unreadable consumer receives the bootstrap request only at an exact, allowlisted claimed origin. A failed allowlist check keeps the channel metadata for a same-page retry.
- `handshake-failure.test.ts`: Host handshake failure classification: the messenger's own acknowledgement timeout becomes `INIT_TIMEOUT` with it as `cause`, other ForgeFrame codes (including a `CLOSED` the consumer sent) are kept, and other values are wrapped as `VALIDATION` with a `cause`.
- `host-transport.test.ts`: A one-time INIT send that waits for bootstrap and never follows teardown, INIT and GET_PEERS data without host-claimed identity, props routing, a `focus()` that waits for window focus with a bounded wait or skips it when the consumer page reports no focus, and teardown, which is not reported as an INIT failure. Peer options are checked before sending: `anyConsumer`, a non-boolean `allTags` and `null` options reject without a request. Peer callbacks run only for `PEER_CALL` requests from the consumer window at its origin. A failed export keeps its callbacks only when it may have been stored: after a delivery attempt that the consumer did not reject with `VALIDATION`.
- `iframe-configuration.test.ts`: CSS and boolean/string attribute encoding, and the sandbox decision (the default tokens, a string kept as given, none for `false`).
- `iframe.test.ts`: Iframe element creation (attributes, styles, CSS variables and dimensions), reserved-attribute guards, rejection of a `sandbox` attribute in any letter case, the resolved sandbox written verbatim or not at all, destruction, visibility, and sizing. `consumer-branch-coverage.test.ts` covers the default, custom and `false` sandbox options and a computed `sandbox` attribute rejected before the iframe exists.
- `index-node-smoke.test.ts`: Public entrypoint imports and component definitions without browser globals. The root entrypoint has no `default`, `ForgeFrame`, `getHostProps`, `isEmbedded`, `PROP_SERIALIZATION`, `CONTEXT`, `EVENT`, `isStandardSchema`, React (`createReactComponent`, `withReactComponent`) or schema-class value export; the `forgeframe/react` entry imports without browser globals and exports only `createReactComponent`, and server rendering a wrapper with React DOM's server renderer emits only its container and creates no instance; `initHost(Component, { consumerOrigins })` returns `null`, while a bare `initHost()` still throws.

- `messenger-routing.test.ts`: Multi-instance channel routing and function bridge response isolation.
- `messenger.test.ts`: Request/response flow, filtering, trust checks (no trust for an opaque origin, its own or a sender's, even through `'*'` or a match-all `RegExp`), targets normalized to an absolute URL's origin with `"*"`, `"/"`, other strings, and opaque-origin URLs rejected before posting, deferred listening, `rejectPending` and `resolvePending` filtering by message type and window, a `VERSION_MISMATCH` reply to a request without a handler, and teardown (no further requests handled, sends and posts refused).
- `package-contract.test.ts`: ESM package exports (`"."` and `"./react"`, each with `types`, `import` and `default`), React and its types as optional peers, both entries in one library build, README package claims, release scripts, release tag validation (including a pre-release tag), the npm dist-tag chosen from the version (`next` for a pre-release, `latest` otherwise) and the Release workflow creating its pack destination, publishing the tarball packed from the verified checkout with it and marking GitHub pre-releases, with `id-token: write` only on the publish job, `contents: write` only on the release job and every action pinned to a commit, and the per-entry bundle size budgets, each counting the shared chunks the entry imports through minified `import` and `export*from` forms and labelled raw and gzip.
- `playground-code-generator.test.ts`: Executes generated iframe, popup, and modal examples, which use the named `create` and `prop` imports, with empty props, composite values, callbacks, quoted names, and styles. - `schema-path-format.test.ts`: Error paths that mix key and index segments.

- `window-helpers.test.ts`: Origin matching, opener and consumer lookup, and iframe/popup detection.

`../require-value.ts` exports `requireValue`, which throws for a missing fixture value instead of letting a test skip an assertion. `../forgeframe-error.ts` exports `forgeFrameError(code, message?)`, an asymmetric matcher for `toThrow`, `rejects.toThrow`, `toEqual` and `toHaveBeenCalledWith` that requires a `ForgeFrameError` instance with that `code`. Assert errors by `code`, which callers branch on, and add message text only when the test is about it. Suites that call `vi.resetModules()` get a fresh error class per test, so they match `name` and `code` with `expect.objectContaining` instead. `../consumer-bridge.ts` reads the callback IDs a consumer sent to its host and calls them through the function bridge's CALL handler, so transport and consumer suites can check whether a callback is still held. `../peer-host-origin.ts`, shared with the integration tests, marks unrendered instances as connected or still loading at a host origin, so peer-discovery tests do not need a rendered host for every peer.

`npm run typecheck` compiles all unit tests and fixtures through `unit/tsconfig.json` with the library's strict settings. Intentionally invalid public inputs use a documented `@ts-expect-error` at the negative fixture only.

## Integration tests (`integration/`)

- `array-prop-transport.test.ts`: Consumer rejection of undefined and sparse array entries before opening or committing an update, recovery, nested values, item defaults, nullable entries, delivery-policy exclusions, an array's `toJSON()` ignored while its entries are checked, record encoders (including computed and setter-only `toJSON` fields), and export rejection that keeps acknowledged data.

- `company-demo-payment-contract.test.ts`: The shared payment amount schema through public consumer render admission and real host bootstrap and update validation. Negative, fractional, and unsafe cents are rejected and leave accepted host state intact; zero, ordinary cents, and the maximum safe integer pass.
- `consumer-host-handshake.test.ts`: Iframe happy path through `create()`, `render()`, `initHost()`, and the INIT handshake, with `ready` resolving to the live props object (consumer props only) and no window global, and the controls on the `Host` handle. - `cross-realm-props.test.ts`: Foreign-window `Date` and record inputs through props and exports; arrays with null prototypes or shadowed `map`; encoded `Date` accessors read once at bootstrap and update; and native and foreign `JSON.rawJSON()` values delivered as the values their text represents through bootstrap, updates, and host exports.
- `naming-and-errors.test.ts`: The origin-named options end to end (`hostOrigins`, `initTimeout`, `context`, `consumerOrigins`, and `host.consumerOrigin`, read-only at runtime); `VALIDATION` errors naming the replacement for `domain`, `timeout`, `defaultContext` and `initHost`'s `allowedConsumerDomains`; matcher strings without a scheme and a reserved `then` prop rejected. A URL outside `hostOrigins` rejects `render()` with `ORIGIN_REJECTED` and leaves the instance open for a retry; `show`, `hide`, `focus` and `resize` take effect before they return.
- `function-prop-bridge.test.ts`: Remote callbacks that outlast the messaging timeout, a pending host export call rejected when the host reconnects or stops answering liveness checks, an unacknowledged props update resolved when the host reconnects (not at the acknowledgement timeout) because the new host's snapshot carries it, running, queued, and later host export calls rejected once the host is destroyed and accepted again after re-initialization, atomic capacity rejection and recovery, live callbacks kept after a failed encoding, omitted callback defaults, a dropped acknowledgement after the receiver installed callbacks, a `BigInt` update rejected as `VALIDATION`, and real callback bridging from host props to consumer callbacks: async results, thrown errors, nested callbacks and dates at bootstrap and update, and retirement of replaced callbacks after acknowledged updates.

## Naming

- Name files `<module-or-scope>.test.ts` after the module or concern under test.
- Name top-level `describe` blocks after the primary module or behavior area.
- Write `it(...)` titles as expected behavior with explicit context, such as the function name for guard and error branches.

## Choosing new tests

Start from a supported public behavior or a reproduced failure, and an agreed public seam. Assert literal expected outcomes that do not depend on the implementation. Prefer a real consumer/host or React DOM integration when the behavior crosses layers, and adapt browser APIs at the environment boundary. Keep focused policy and resource fault-injection cases when they add distinct evidence; remove wiring assertions that public tests supersede.

Coverage thresholds sit just under the current totals (statements 99, branches 96.5, functions 99, lines 99), and the origin, allowlist, sandbox and window-name checks (`consumer-origin-policy.ts`, `iframe-configuration.ts`, `name-payload.ts`, `messenger.ts`, `security.ts`, `origin-pattern.ts`) must stay fully covered. When a change lowers coverage, add the missing test rather than lowering a threshold.

Check acceptance and, where meaningful, rejection and recovery. Keep schema inputs and normalized outputs explicit in fixtures, and run `typecheck:tests` as well as Vitest. Confirm a new test fails when the behavior is removed, then restore the source before final validation. Coverage points to candidates; supported behavior and failure impact decide whether a test is worth adding. Do not add casts, mocks, exclusions, or threshold changes only to reach 100%.
