# Playground product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Developers and evaluators exploring ForgeFrame. The company demo places them in the role of veterinary reception staff collecting payment for an invoice.

## Product Purpose

Make cross-origin iframe and popup integration tangible through working examples. A successful company demo returns a simulated payment result to the merchant and updates the invoice.

## Operating Context

The existing playground is a configuration editor and browser test lab. The additional company demo is a compact, immersive invoice portal. Experience and Technical are presentation modes of the same running app; switching preserves invoices, active integrations and callback history.

## Capabilities and Constraints

Use actual ForgeFrame communication between separate consumer and host origins. Payment processing is simulated, with success, decline/retry and cancellation. Three fixed AUD invoices reset on refresh or Reset demo. No backend or persistent storage. Preserve the existing playground, public library contracts and test lab.

Technical mode shows the live props, callback arguments, acknowledgements and lifecycle events, with the actual authored consumer/host/contract source. Explain ownership, initialization and callback return behavior through useful TSDoc.

## Brand Commitments

Pip Veterinary and Harbor Pay are fictional demo brands with authored branding, copy and sample data. Use navy and orange, self-hosted Open Sans, clear native controls and visible focus. The original puppy is a small decorative companion in the invoice-list footer. Keep the original diagnostic playground separate. Maintain the application directly in code and verify visual changes at desktop and mobile widths.

## Evidence on Hand

The playground's consumer/host configuration, shared payment contract, authored source, sample invoices and browser test routes establish the current behavior. Asset provenance and font licensing live in `assets/README.md`. Keep company content, names, logos and imagery original.

## Product Principles

- The main experience feels like a working product; integration details are optional.
- Keep merchant invoice state and provider form state with their respective applications.
- Make demonstrations repeatable and clearly simulated.
- Explain outcomes and give a recovery action.
